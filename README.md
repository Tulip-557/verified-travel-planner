## 它解决什么问题

让 AI 写攻略，最要命的不是文笔，是**分不清哪些数字能信**：

```
「高德返回车程 18 分钟」      ← 机器实测
「某篇攻略说这边很好逛」       ← 个人体感
「听说门票大概 300 多」        ← 道听途说
```

三者字面一模一样，可信度差三个数量级。而旅行时踩坑的代价是真实的：
到了景区发现闭馆、赶不上末班车、门票比预算贵一倍。

这个项目干两件事：

1. **把可信度变成看得见的东西**——每个数字后面直接标证据等级（四级 + 死线）；
2. **把「忘了查」变成机器拦得住的东西**——交付前跑九道闸门，不过就不给你成品。

**主张一句话**：宁可输出「这家店人均未查到，请自行比价」，
也不拿一个估算冒充查实结果。

## 三个核心机制

### 1️⃣ 证据四级 + 死线

等级标直接写在正文里、紧跟那个数字：

```
4.2 公里，车程 18 分钟（2026-09-27 查·高德路线）[A]
本地菜馆（人均 60）[B]（点评 4.6 + 地图在营，2026-09-27 核）
14:00-16:00 常有雷阵雨 [C·单源·小红书2026-09帖]
门票价未核实 [D]——请到官方公众号搜「XX景区门票」确认
```

| 等级 | 含义 |
|---|---|
| **`[A]`** | 工具实证：高德 API、官方页面等，**必须带查询时戳** |
| **`[B]`** | 双源印证：两个独立来源相互对上 |
| **`[C]`** | 单源线索：只有一个来源，或来自社区内容 |
| **`[D]`** | 未核实：查不到就如实标，**必须给出用户可自查的出路** |

**死线**：票价、营业时间、车次余票、距离与车程——这几类只要写进正文，
就不允许标 `[C]`/`[D]` 冒充确定信息；查不到就写「未核实 + 出路」，不许用「大约」糊过去。

渲染后是一枚枚彩色小徽章（越实越绿、越虚越红），鼠标悬停显示等级全称。

### 2️⃣ 九道闸门（交付前自动拦）

| 闸门 | 拦什么 |
|---|---|
| `unittest` | 153 条机器断言：闸门自身的输入、退避、比对行为回归 |
| `validate_skill` | 自指校验：文档声称的能力与代码事实是否一致（19 条规则） |
| `consistency` | 版式一致性：有人手改 HTML、漏了导航、留了占位符 |
| `source_audit` | 证据标注纪律（8 条规则）：时戳、双源、死线、出路、来源闭环 |
| `compact_check` | 精简版质量：双档覆盖、约束数字不丢、证据不降级 |
| `evaluate` | 确定性可行性：闭馆时间冲突、换乘余量不足、单日跨度过长、预算不闭合 |
| `claim_audit` | 内容真实第 1 层：实采值必须如实进路书（采集 16 写成 15 会红） |
| `echo_audit` | 内容真实第 2 层：来源回声——抓取引用页，验证「页面上真有那个值」 |
| `cross_check` | 内容真实第 3 层：独立源核查——「双源印证」是不是互相抄的一家 |

> **「内容真实」三层链**（上表最后三行）：标注纪律只保证「标得规范」，不保证
> 「那句话是真的」。标了 `[A]` 的断言是否属实，靠三层机器校验接力回答——
> **① `claim_audit`（声明↔留痕）**：采集默认留痕（快照内嵌 `raw_calls`，key 脱敏），
> 实采的段时长与段车费被改写或丢弃即 FAIL（采集 16 分钟写成 15 分钟会现形）；
> **② `echo_audit`（声明↔来源网页）**：抓回引用页正文，验证声称的数字/时刻/关键短语
> 真在页面上——值抽取认中文数字（「四十二分钟」↔ 42）、多源取最优、JS 壳兜底，
> 抓不到的只 WARN 不判死（「看不到」≠「没有」）；**③ `cross_check`（来源↔来源）**：
> 各来源正文做 4-gram 重合比对，拆穿「互相转载充双源」。
> **三层全过仍 ≠「数字一定对」**——链条止于「页面怎么说」，引用页自身的对错
> 仍需临行前用官方渠道复核（设计与边界见 `references/echo-cross.md`）。

另有一条**不阻断**的时效体检 `freshness`：按出发日反推，哪些动态数字该重查了。

一条命令跑完全部：

```bash
python verified-travel-planner/tools/ship.py     # 全绿才算可交付；有问题退出码 2
```

其中还有一条最硬的**渲染复现**：由事实源重新渲染，与既有 HTML **逐字节比对**——
渲染器偷偷改了样式、产物与源不一致，这一条会先炸。

> 这套闸门是**给自己用的**：开发过程中它抓出过「门票标了够不着的等级」
> 「精简版把末班车时间压没了」「evaluate 喂错文件层级拿到假的满分」等真问题，
> 每一条都固化成了断言（`tests/` 153 条）。

### 3️⃣ 双版本交付 + 单文件可开

- **完整版**：信息全，用于行前细读；
- **精简执行版**（`--compact`）：`sections` 与 `days[].slots[].body` **同字段双档**，
  按「换写法」而非「压措辞」瘦身，**约束类数字（末班车、停止入场、留足余量）一律不丢**；
  首屏带逐日速览表。
- 两份产物都是**单文件 HTML**：配图 base64 内联，**断网可开**，微信传文件即可分享。

## 工作流

```text
阶段 0  需求采集（逐项问清，缺失用默认值并声明）
  ↓
阶段 1  能力自检（实测数据源可用性，记录降级项）
  ↓
阶段 2  目的地筛选（给方向，用户拍板后再做详细方案）
  ↓
阶段 3  实查复核（硬数字 · A 级信息采集，逐条带时戳）
  ↓
阶段 3.5 社会情报采集（玩法与体验 · B/C 级；默认执行，跳过须留痕）
  ↓
阶段 4  路书产出（六维度 + 双写同步 + 情报来源声明）
  ↓
阶段 5  交付自查（30 项机械核对，机械可查部分全绿才可交付）
  ↓
阶段 5.5 交付分发（附未核实项清单与覆盖声明）
  ↓
阶段 6  行程中陪伴 / 复盘回流（情报回流进库，供下次复用）
```

**阶段 3 与 3.5 是一根扁担的两头**：3 采「硬数字」（车程/票价/营业时间/余票），
3.5 采「玩法与体验」（怎么玩、什么时候去、值不值得多待）。
两者信息不重叠、证据不互相顶替——**3.5 永远不产出数字，3 也永远不告诉你哪里好玩。**

## 它能做什么

- **实况数据采集**：高德 POI 搜索 / 周边 / 地理编码 / 驾车与公交路线 / 天气（含 4 天预报窗口判定）
- **可行性判定**：按活动时间窗、营业时间、闭馆日、换乘缓冲、单日跨度、预算做确定性检查
- **内容校验**：机票报价跨源一致性、酒店报价晚数推断与总价折算、车次席别归一
- **渲染**：事实源 JSON → 单文件 HTML（完整版 / 精简执行版），含基准骨架一致性校验
- **交付自查 + 九道闸门 + 一键回归**
- **行前公告扫描**（`bulletin.py`）：闭馆/调价/管制/新开/活动五类事件，出官方渠道 sweep 查询清单，`--check` 校验分级（公告类死线只认 `[A]`），首屏公告条提示不改行程
- **口碑体检**（`review_trust.py`）：评论区水军/推广**信号**（复读指纹/推广标记/立场错配/同日爆发）——只出信号不结论，不产「调整后评分」
- **脱敏双轨**：从一份源路书派生出「对外版（脱敏）」与「自用版（含情报原档）」
- **社会情报**：21 条渠道的能力矩阵与采集计划（本机实测可用 9 条），口碑层只出「信号」不出结论
- **证据健康度一页纸**（`evidence_report.py`）：聚合五道内容闸门的结构化结论 + 徽章分布 +
  `[D]` 未核实清单，生成单文件 HTML《可信度概览》——报告是交代，不是评分
- **改版审计**（`revision_audit.py`）：两版事实源的声明级 diff——数值变化、证据等级升降；
  降级须在 `meta.revision_log` 显式声明（写清 why），`--strict` 下悄悄降级即退出码 2
- **行程质量评分**（`quality_report.py`）：节奏疲劳 / 成本效率 / 体验匹配 / 衔接稳健——
  四维、逐点可解释（每个得分挂具体活动与规则），判「排得好不好」而不与 evaluate 的
  「排不排得通」重复
- **动线优化建议**（`route_optimize.py`）：最近邻 + 2-opt 给出更省的到访顺序，直线口径
  【估算】明说非实测车程；**只出建议，绝不写回事实源**

## 它明确不做什么

- **不代订、不支付、不抢票**：全流程只读；不输密码、验证码、身份证号
- **不闭眼重试**：同一信息最多查 2 轮，查不到就标「未查到」并给人工选项
- **遇到风控一次即停手**，换路径而不是硬闯
- **不拿 AI 摘要当证据**：搜索摘要只作线索，结论必须落到具体页面或官方源
- **不估算距离/时长**：没有地图能力时一律标 `[D]`，绝不填一个看着合理的数字

## 这份东西的定位

**它不是「旅行攻略生成器」，是一份「把 AI 说过的数字变成可被机器校验」的参考实现。**
旅行只是它第一个落点——真正可复用的是那套方法：**先查实、再写作、然后自己把自己查一遍**。

### 为什么它不是又一个攻略 skill

同类项目里，**没有一个**有等价的「证据分级 + 死线 + 闸门」；更关键的是立场相反：

| | 主流做法 | 本项目 |
|---|---|---|
| 地图 API 失败时 | 回退到 LLM 知识库数据，并把「永不失败」当卖点 | **不降级**：没有地图能力时，POI 与距离一律标 `[D]`，宁可少写也不编 |
| 「有没有问题」怎么判 | 打印一份报告，退出码 0 | **九道闸门全部有退出码**，`FAIL` 即 `2`，能被程序感知 |
| 产物与源不一致 | 靠人看 | **逐字节比对**：由事实源重渲染，与既有 HTML 逐字节一致才算过 |
| 文档里说的能力 | 靠自觉 | **自指校验**：连「本工具有几条规则、几处断言」都由机器查 |

一句话：**别人的可用性优先，这里的可信度优先。** 这是选择，不是功能多少。

### 已知边界（诚实清单，先看这些再决定用不用）

1. 🟠 **「内容真实」审到什么程度——三层链，仍不是终点。**
   「标了 `[A]` 的那句话是不是真的」被拆成三层机器校验，2026-10-01 起全部落地：
   **第 1 层 `claim_audit`**（声明↔留痕）：高德采集默认留痕（快照内嵌 `raw_calls`），
   实采值（段时长、段车费）必须如实进路书，被改/被丢即 FAIL——「采集 16 分钟写成
   15 分钟」的数字幻觉会现形；**第 2 层 `echo_audit`**（声明↔来源网页）：抓取引用页
   正文，验证声称的数字/时刻/关键短语真的在页面上，死线类对不上即 FAIL；
   **第 3 层 `cross_check`**（来源↔来源）：把各来源的页面正文做重合比对，
   「双源印证」若是互相转载的一家，[B] 的地基会被拆穿。
   **仍然够不到的**：页面在核实日期之后合法改版（echo 以时戳提示重查，不判死）；
   JS 渲染页抓不到正文（如实列 UNREACHABLE）；语义等价改写（机器只认数字与短语
   回声）；**引用页自身内容就是错的**（链条止于「页面怎么说」）。
   → 所以：**「过了闸门」= 「说得出来源 + 实采值可寻 + 页面回声 + 独立性过关」，
   仍 ≠「数字一定对」。** 请把交付物里的「未核实项清单」当成真正的兜底。
2. **需要自备高德 key**：没有它就没有实况数据，只能产出全是 `[D]` 的路书。
   个人认证账号的**关键字搜索**日配额很低（百次量级）。
3. **采集类能力依赖本机环境**：无头浏览器探针、登录态 profile 需各自自建；
   **核心闸门（渲染 / 自查 / 可行性 / 一致性）不受影响**——它们零第三方依赖。
4. **天气只有约 4 天预报窗口**，属临行前能力，规划期不写未来天气。
5. **铁路未接入**：车次需你或别的渠道提供，本工具只校验其一致性与新鲜度。
6. **社媒渠道有风控**：小红书 / 抖音 / 知乎等在本机实测不可读（IP 风控，非登录墙）；
   能读的渠道只作**信号**，天花板为 `[B]`，永不产出数字。
7. **平台**：核心能力 Windows 已实测，其他平台标「未实测」而非「不可用」。

```bash
python verified-travel-planner/tools/set_amap_key.py          # 交互式配置
```

## 使用

### 环境体检

```bash
python verified-travel-planner/tools/doctor.py
```

8 项检查：Python 解释器 / 时区数据库 / 检查引擎符号 / 高德 key / 随包资产 / 第三方依赖 /
平台绑定项 / 机器级私有状态。核心项全 `READY` 才算环境可用。

### 统一 CLI（14 个命令，先看 `--help`）

```bash
CLI="python verified-travel-planner/tools/travel_planner.py"
$CLI --help                 # 全部命令
$CLI validate-request  ...  # 需求采集校验（缺项 -> 追问）
$CLI search-places     ...  # 查高德 POI（需 key）
$CLI amap-snapshot     ...  # 一次采集坐标 + 路线 + 周边（需 key）
$CLI weather           ...  # 实况 + 4 天预报（需 key）
$CLI evaluate          ...  # 确定性可行性检查（排不通就不给，退出码 2）
$CLI validate-plan     ...  # 方案内容完整性（内连带跑机票/酒店校验）
$CLI compile-research  ...  # 社区线索汇编成景点卡
```

### 渲染与自查


## 注意事项

**关于边界**

1. **本工具只读**：不代订、不支付、不改签；任何要输密码、验证码、身份证的环节都不碰。
2. **降级要留痕**：数据源不可用时如实记录降级项，不静默假装一切正常。
3. **不硬凑用户期待**：用户给的线索核实后发现记错了，如实回告。

**关于数据**

4. **证据分级审「标注纪律」，「内容真实」靠三层链兜着**——详见上文〈已知边界〉
   第 1 条：`claim_audit`（声明↔留痕）+ `echo_audit`（声明↔来源网页回声）+
   `cross_check`（来源独立性/转引检测）三层全落地，但**「页面里有」≠「页面说的对」**，
   链条止于「页面怎么说」；引用页自身的对错，仍需你临行前用官方渠道复核，
   交付物里的**「未核实项清单」**就是为这一步准备的。
5. **高德配额**：个人认证账号的**关键字搜索**日配额很低（百次量级），
   地理编码与路径规划宽松得多（千次量级）——超过就换接口，别死磕。
   报 `CUQPS_HAS_EXCEEDED_THE_LIMIT (10021)` 是**并发/QPS 限流，不是日配额**；
   客户端已内置指数退避重试。
6. **天气预报窗口只有约 4 天**，属临行前能力；行程还早时只能给气候背景，会明说。
7. **铁路未接入**（无官方 12306 server）：车次需你或别的渠道提供，
   本工具负责校验其一致性与新鲜度，不负责抓取。
8. **社区/社媒渠道有风控**：小红书、抖音、知乎等在本机实测不可读（IP 风控，非登录墙）。
   能读的渠道只作**信号**，永远不产出数字。

**关于环境**

9. 核心闸门（渲染 / 自查 / 可行性 / 一致性）**纯标准库、与平台无关**；
   无头浏览器探针在 **Windows 已实测**，其他平台标「未实测」而非「不可用」。
10. 分发时必须是**真实副本**（目录联接不能直接打包）。
